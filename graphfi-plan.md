# graphfi — план работ

Задание для агента. Личный журнал просмотров кино с аналитикой — замена
вырезанному личному кабинету Кинопоиска.

Владелец смотрит кино систематическим обзором по годам, начиная с 1920-го.
Главная ценность продукта — **видеть, как заполняется картина по мере
продвижения по годам**, а не вести каталог. Всё остальное подчинено этому.

---

## 0. Рамки

**Стек:** Python 3.12, Django 5, SQLite, чистый SVG для диаграмм.
**Без:** JS-фреймворков, JS-библиотек графиков, CSS-фреймворков, Docker,
Celery, REST API, регистрации пользователей, тёмной/светлой темы.

Один пользователь, локальный запуск. Этап 2 (публикация на домене) — позже,
но код пишется так, чтобы переход был чисто инфраструктурным.

**Зависимости:** только `Django` и `requests`. Добавление любой третьей
зависимости требует явного обоснования в коммите.

**Правовые ограничения — обязательны к соблюдению:**
- Изображения (постеры, фото персон) **никогда не скачиваются на диск**.
  В базе хранятся только URL на CDN TMDB. Это не оптимизация, это условие.
- Метаданные берутся только из TMDB API и Wikidata. **Скрейпинг Кинопоиска,
  IMDb или любых других сайтов запрещён.**
- В шаблон подвала при публикации: «This product uses the TMDB API but is
  not endorsed or certified by TMDB».

## 1. Модель данных

Четыре таблицы. Ключевое решение — **одна таблица `Credit` вместо отдельных
для актёров, режиссёров и прочих**: все запросы вида «средняя оценка по
персоне» становятся одинаковыми и параметризуются ролью.

```
Genre
  slug       SlugField unique      # ключ, не меняется никогда
  label      CharField             # подпись, меняется свободно
  order      PositiveSmallInteger

Person
  name, original_name
  tmdb_id    Integer null unique
  wikidata_id
  photo_url  URLField              # ссылка, НЕ файл
  birth_year, death_year

Film
  title, original_title
  year       Integer indexed
  tmdb_id    Integer null unique
  imdb_id, wikidata_id
  poster_url URLField              # ссылка, НЕ файл
  runtime, country
  rating     PositiveSmallInteger null, валидаторы 1..10
  watched_at DateField null indexed
  note       TextField
  genres     M2M -> Genre
  UniqueConstraint(title, year)

Credit
  film       FK -> Film   related_name="credits"
  person     FK -> Person related_name="credits"
  role       CharField choices: dir | act | comp | dop | writ
  character  CharField
  billing    PositiveSmallInteger  # порядок в титрах
  UniqueConstraint(film, person, role)
  Index(person, role), Index(role)
```

**Оценки — целые 1–10.** Не Decimal, не половинки. `null` = не смотрел.

**Жанров не больше 3 на фильм.** Лимит проверяется в форме админки
(`clean_genres`) и в `Film.clean()`, не на уровне схемы.

### Закрытый словарь жанров

Живёт в `films/genres.py` как список кортежей, заливается командой
`seed_genres`. Ничего вне списка добавить нельзя — иначе через год будут
«нуар», «noir» и «фильм-нуар» тремя тегами и агрегация посыплется.

```
adventure     Приключения        musical       Мюзикл
animation     Анимация           mystery       Детектив
comedy        Комедия            noir          Нуар
crime         Криминал           romance       Мелодрама
documentary   Документальное     scifi         Фантастика
drama         Драма              serial        Сериал-выпуск
fantasy       Фэнтези            spy           Шпионское
historical    Историческое       swashbuckler  Плащ и шпага
horror        Хоррор             thriller      Триллер
war           Военное            western       Вестерн
```

Там же — `TMDB_GENRE_MAP`: числовые id TMDB → наши слаги. `noir`, `serial`
и `swashbuckler` в TMDB отсутствуют и ставятся только руками. Это ожидаемо:
именно эти теги и есть авторская разметка, а не импорт чужой.

## 2. Архитектура модулей

Жёсткое разделение, нарушать не надо:

```
films/
  models.py      только модели
  stats.py       агрегаты. Чистые функции, ничего не рендерят,
                 возвращают питоновские структуры
  charts.py      генерация SVG. Принимает результат stats.py,
                 возвращает строку. Не ходит в базу
  bulk.py        разбор текста пакетного ввода. Не ходит в базу
                 при парсинге, только при применении
  resolver.py    TMDB + Wikidata. Django не импортирует вообще —
                 тестируется и переиспользуется отдельно
  views.py       склейка stats + charts + шаблон. Логики нет
  admin.py       редактирование
```

`resolver.py` возвращает дата-классы `FilmData` / `PersonData`, а не модели.
Превращение их в записи базы — работа команды `resolve`.

## 4. Диаграммы

Все — SVG, собранный строками в `charts.py`. Общая цветовая шкала:
оценка 1 → холодный тусклый `#3D4E5A`, 5.5 → `#8C8A78`, 10 → тёплый яркий
`#F0B44E`. Метафора — лампа проектора. Функция `rating_color(value)`,
`None` → цвет пустого кадра `#1B242D`.

Интерактив без JS: точки и ячейки оборачиваются в `<a href>`, подсказки —
через `<title>`. Никаких кастомных тултипов.

**1. Плёнка (`rail_svg`) — сигнатурный элемент.**
Кадр на каждый год от первого просмотренного до последнего, включая годы
без просмотров. Заливка кадра = цвет средней оценки за год, пустой год =
цвет пустого кадра. Сверху и снизу — перфорация. Клик по кадру →
`/films/?year=NNNN`. Под лентой — подписи круглых годов через 10.

Это и есть главная картинка прогресса. Всё остальное вторично.

**2. Диаграмма оценок (`scatter_svg`).**
X = год выпуска, Y = оценка 1–10. Точка на фильм, цвет по оценке. Поверх —
линия средней по годам. Совпадающие точки внутри одного года разводятся по
горизонтали, чтобы не сливались. Переключатель оси: год выпуска ↔ дата
просмотра (во втором режиме линия средней не рисуется).

**3. Жанры (`genre_bars_svg`).** Горизонтальные полосы, длина и цвет = средняя,
справа число фильмов. Сортировка по средней.

**4. Матрица жанр × десятилетие (`heatmap_svg`).** Ячейка = средняя оценка,
цветом и числом. Жанры отсортированы по общему количеству фильмов.

**5. Гистограмма (`histogram_svg`).** Распределение оценок 1–10.

## 5. Таблицы персон

Для каждой роли: имя, фото, количество просмотренных фильмов, средняя оценка.
Сортировка по количеству, затем по средней.

**Важно:** персоны меньше чем с `MIN_FILMS_FOR_RANKING` (по умолчанию 3)
фильмами выносятся в свёрнутый блок `<details>` под основной таблицей.
Средняя по одному фильму — шум, и без порога топ забьётся случайными людьми
из одной удачной картины.

## 6. Ввод данных

### Пакетный ввод `/add/`

Формат строки: `Название | год | оценка | дата | жанры`
Обязательны первые два поля. Дата — `ДД.ММ.ГГГГ` или `ГГГГ-ММ-ДД`.
Жанры — слаги через запятую, максимум 3. Строки с `#` и пустые пропускаются.

Два шага: «Проверить» показывает разобранную таблицу с пометкой
«новый / обновится» и список ошибок с номерами строк; «Сохранить» применяет.
Существующие фильмы (по паре название+год) обновляются, не дублируются.

### Резолвер метаданных

```
python manage.py resolve            # интерактивно, выбор из кандидатов
python manage.py resolve --auto     # первое совпадение по году
python manage.py resolve --id 42    # один фильм
python manage.py resolve --force    # в том числе уже связанные
```

Порядок: TMDB `/search/movie` по названию и году → показать кандидатов
(название, оригинальное название, год) → по выбору дёрнуть
`/movie/{id}?append_to_response=credits`.

Из TMDB: постер, оригинальное название, хронометраж, страна, жанры (через
`TMDB_GENRE_MAP`, максимум 3), каст (первые 12 по `order`), из crew —
Director, Original Music Composer / Music, Director of Photography,
Screenplay / Writer.

**Затем Wikidata.** Для кино 1920–1950-х у TMDB операторы и композиторы
пусты сплошь и рядом. Один SPARQL-запрос к `query.wikidata.org` по IMDb-id
(`wdt:P345`) добирает `P57` режиссёр, `P344` оператор, `P86` композитор,
`P58` сценарист — **только те роли, которых не дал TMDB**. Пауза 1 с перед
запросом, свой User-Agent, ошибка Wikidata не должна ронять весь резолв.

Резолвер никогда не затирает уже заполненные поля — только дополняет пустые.

### CSV

```
python manage.py export_csv --out films.csv
python manage.py import_csv films.csv --dry-run
python manage.py import_csv films.csv
```

Аварийный выход для массовых правок. Матчинг при импорте: `id` → `tmdb_id` →
пара «название + год». Состав через CSV не ходит — это работа `resolve`.
`--dry-run` выполняет всё в транзакции и откатывает.

## 7. Оформление

Палитра проекционной будки — холодный слейт и янтарь лампы:

```
--ground #0f151b   --panel  #171f27   --rule   #27333e
--text   #dcd7cc   --muted  #7e8b97   --amber  #e8a33c
```

Шрифты с Google Fonts: `Big Shoulders Display` для заголовков (узкий,
маркизный), `IBM Plex Sans` для текста, `IBM Plex Mono` для всех чисел —
годов, оценок, счётчиков.

Постеры и фото — с лёгким `grayscale(.35)`, снимается при наведении.
Один CSS-файл, никаких препроцессоров. Обязательный минимум: адаптив до
мобильного, видимый `:focus-visible`, уважение `prefers-reduced-motion`.

## 8. Этапы

Каждый этап заканчивается работающим состоянием. Не переходить к следующему,
пока предыдущий не проверен вручную в браузере.

**Этап 1. Каркас.**
Проект, приложение, четыре модели, миграции, `seed_genres`, суперпользователь.
Готово когда: через админку можно завести фильм с жанрами и составом.

**Этап 2. Админка как рабочее место.**
`CreditInline` с автодополнением персон, `list_editable` для оценки и даты
просмотра, фильтры по оценке/жанру/году, поиск, `filter_horizontal` для жанров,
валидация лимита в 3 жанра.
Готово когда: пачку оценок можно проставить прямо в списке, не заходя в карточки.

**Этап 3. `stats.py`.**
Все агрегаты. Проверяются в `manage.py shell` на живых данных до того, как
появится хоть один шаблон.
Готово когда: каждая функция вызывается и возвращает осмысленное.

**Этап 4. `charts.py` + профиль.**
SVG-функции и страница `/`. Сначала плёнка и диаграмма оценок, потом остальное.
Готово когда: профиль открывается и лента отражает реальные данные.

**Этап 5. Список и карточки.**
`/films/`, `/film/<pk>/`, `/person/<pk>/`, `/people/`.

**Этап 6. Пакетный ввод.** `/add/` с двухшаговым подтверждением.

**Этап 7. Резолвер.**
Сначала `resolver.py` отдельно и проверка из shell на 3–5 фильмах разных
десятилетий, включая один немой 20-х годов — там всплывут дыры в TMDB.
Потом команда `resolve`. Потом Wikidata-добивка.

**Этап 8. CSV.** `export_csv`, `import_csv`.

**Этап 9. Оформление.** CSS, шрифты, адаптив, доступность.

## 9. Приёмка

- `python manage.py check` без предупреждений
- Профиль открывается на пустой базе без исключений — все диаграммы корректно
  обрабатывают отсутствие данных и показывают осмысленную пустую заглушку
- Фильм без постера, без жанров, без оценки и без состава рендерится везде
- Пакетный ввод на кривом тексте показывает номера строк и причины, ничего
  не сохраняя
- Повторный прогон `resolve --force` не создаёт дублей персон и участий
- `import_csv --dry-run` не меняет базу
- Ни одного скачанного изображения на диске
- Мобильная ширина 380px не ломает вёрстку

## 10. Соглашения

- Русский язык в интерфейсе, `verbose_name` у всех полей моделей
- Комментарии — только там, где объясняют **почему**, а не что делает код
- Никаких `print` в продакшн-коде, для команд — `self.stdout.write`
- Внешние запросы всегда с `timeout`
- Строки формата и SVG — f-строки, экранирование пользовательских данных
  через `html.escape` перед вставкой в SVG
- Секреты только из окружения, в репозиторий не коммитятся
